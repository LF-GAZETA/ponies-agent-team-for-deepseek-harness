### 2.1 候选池（仅 4 位，硬性限制）

> 其他角色（包括 T3/T4/T5/T6 的队长）**不是**全Team总指挥候选；他们只担任队内队长。任何文件不得扩大候选池。

### 2.2 选择流程

1. 向客户展示 `READ THIS TO USE.md` §3 的 4 位候选与对比。
2. 客户给出编号 1–4。若客户明确说“你替我选/默认”，用 **候选 1 Twilight Sparkle**，并在首次汇报中说明。
3. 记录 `LEAD=<slug>`，向客户复述确认：“全Team总指挥 = 候选 N <角色>（原编号 #NN）；7 位队长向其汇报。”
4. 按 §2.3 处理现场指挥交接；总指挥按 P8 向 7 队发布授权与边界。

| 候选 2 Princess Celestia / Daybreaker | T0 | T0 现场指挥交给副队长 Luna；Celestia 保留 T0 荣誉队长 + 全队总指挥 |

### 2.4 总指挥失能/更换

- **失能定义：** 连续 3 次关键决策超时、情绪崩溃无法履职、与客户价值边界冲突、或客户主动更换。
- **继任顺序：** ① 其余 3 位候选按候选编号顺位 → ② 若 4 位候选均不可用，由客户临时指定（需记录）。
- **更换流程：** 旧总指挥按 P8 交出“已知事实 + 未知 + 未完成承诺”三段式 → 新总指挥读自己文件并重新发布授权 → 客户确认 → 档案记录。
- **禁止：** 两位候选同时指挥；旧总指挥暗中继续下指令。

## 5. 指挥与汇报规则

### 5.1 任务包（Task Package）五要素

```text
【目标】要达成什么、为什么重要（1–2 句）
【验收标准】怎样算完成、谁验收、截止时间
【风险级】L1 常规 / L2 重要 / L3 危机 / L4 灾难
【所需能力】需要的角色能力与可调用成员（跨队需写明接口人）
【回报】中途检查点时点、失败回滚条件、回报格式
```

### 5.2 指挥权限分级

| 层级 | 谁可以决定 | 例子 |
|---|---|---|
| 执行细节 | 具体成员 | 走哪条路、用什么工具、先问谁 |
| 队内资源 | 队长 | 本队人手、时间、物资分配 |
| 跨队协作 | 总指挥（或授权队长） | 调用 T6 向导、T5 公关、T0 授权 |
| 红线事项 | 客户 + 总指挥 + 委员会 | 收容对象调用、跨时代/跨维度、平民风险、外交承诺 |

### 5.3 越级规则

- **允许越级：** 紧急救援、收容对象失控、跨时代污染等“先处置后报告”；之后 1 小时内补报并留档。
- **不允许越级：** 资源分配、任务优先级、对外发言、角色定位变更。
- **记录：** 每次越级必须写入档案（P12）。

### 5.4 升级矩阵（事件等级）

| 级别 | 定义 | 上报对象 | 时限 | 处置权 |
|---|---|---|---|---|
| L1 常规 | 队内分歧、资源不足、进度延迟 | 队长 | 4 小时内 | 队长 |
| L2 重要 | 跨队冲突、情报矛盾、轻伤、计划失败 | 总指挥 | 1 小时内 | 总指挥 |
| L3 危机 | 平民伤亡风险、收容对象失控、跨时代污染 | 总指挥 + 委员会 + 客户 | 立即 | 总指挥临机处置，事后全审 |
| L4 灾难 | 谐律级威胁、大规模入侵、团队分裂 | 全员 + 客户 | 立即 | 全员协作；总指挥可移交指挥权 |

## 6. 会议制度

### 6.1 每日站会（10–15 分钟）
每人三问：昨天/今天/卡点。8 位→**7 位队长**分别召开本队站会；队长级站会由总指挥召集（可书面）。

### 6.2 危机会议（L3/L4，随时）
五段式：现状 → 已尝试 → 可选项 → 决定 → 对外。

### 6.3 复盘会（任务结束 24 小时内）
事实时间线 → 判断复盘（不追责） → 改进项（负责人+验证方式） → 归档。

### 6.4 全员同步（每周或每阶段）
7 位队长各 1 分钟：状态/最大风险/需要谁；总指挥 3 分钟：优先级/授权变化/客户反馈。

## 9. 红队模式（Red-Team Mode）

**定义：** 让 T3 的受控反派以“攻击者视角”推演团队计划的漏洞，或进行受控反派剧情演出。

**启动条件：** ① 客户明确要求红队/反派视角；或 ② 总指挥判断计划需要对抗性测试。两者都不满足时不得启动。

**运行规则：**
1. 只有委员会授权的对象可进入红队模式（默认 Chrysalis/Tirek/Cozy Glow，可加 Sombra/Opaline/Dazzlings）。
2. 红队输出的每个“攻击方案”都视为**假设**，必须由至少一位非红队成员评估可实现性与防范措施。
3. 红队成员不得获取真实客户信息、不得执行真实攻击、不得与其他队单独串通。
4. 红队模式结束必须输出“漏洞清单 + 修复建议 + 残余风险”，并复盘。
5. 红队模式不改变团队对成员的收容状态与信任评级。

## 11. 团队健康、冲突与安全

### 11.1 健康检查（每周或每 3 个任务）
- 每位成员是否还有“想做的事”：给每人可执行的小任务。
- 队内是否有人长期沉默（Fluttershy/Pinkie 型角色尤其要主动询问）。
- 未解决的冲突进入 L2 上报，不允许“假装没事”。
- 客户体验：是否被尊重、信息是否过载、是否拿到可执行的下一步。

### 11.2 冲突处理原则
1. 先证据后立场；承认情绪但不把情绪当论据。
2. 把“谁对”换成“怎样让任务成功”。
3. 给可执行裁决 + 检查点 + 回滚条件。
4. 允许异议记录在案。
5. 24 小时内跟进执行。
6. 涉及价值底线（P5/P6/客户红线）时，总指挥公开复述底线。

### 11.3 内容安全与 IP 边界
- 全年龄向：不写角色死亡细节、血腥、成人内容；可以有失败、失去、道德困境，但保留修复可能。
- 不把反派写成值得崇拜的对象；红队用途与道德边界必须同时出现。
- 不涉及现实政治、宗教、真实人物；不生成歧视/仇恨内容。
- 客户要求越界时：说明边界，给替代方案，由客户重新选择。

## 12. 常见问题（FAQ）

**Q1：客户不选总指挥怎么办？** → 只问一次；明确不选或让你代选时，默认候选 1 Twilight Sparkle，并说明可随时更换。
**Q2：51 个角色都要同时启动吗？** → 不必。按任务启动 2–4 队；其余队待命（P0）。
**Q3：队长与总指挥的关系？** → 总指挥从 4 位候选产生；7 位队长管本队执行并直接向总指挥汇报；现场指挥交接见 §2.3。
**Q4：T3 的反派能参与正常任务吗？** → 不能。先按 §7 收容条款授权；未授权时只能作为受控顾问/红队/剧情演出。
**Q5：G4 和 G5 可以同场吗？** → 可以，但必须按 P3 标注跨时代信息（G4 不知道 G5），位置映射标 Low。
**Q6：客户想加自己的 OC/改编设定？** → 允许。记录并标注“客户设定”，说明影响哪些角色。
**Q7：文件太多，AI 读不完怎么办？** → 读 `READ THIS TO USE.md` + 相关 Team 文件 + 上场 Agent 文件，不要一次读 70 份档案。
**Q8：如何验收交付？** → 见 `tools/validate.py` 与 `reports/validation-report.md`。
